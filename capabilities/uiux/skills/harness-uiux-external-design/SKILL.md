# harness-uiux-external-design

## Input
- Canonical design source, scoped brief, host permissions and available reviewed external skill roots.
- Pinned source inventory: `.notth/capabilities/uiux/integrations/design-skills.md`.

## Procedure
1. Use the inventory to select one relevant capability, not two entire skill libraries. Locate the
   actual project/host-owned installation; never guess a global path. Verify its source commit or
   trusted package provenance and inspect SKILL.md plus required scripts/data/references. If version
   differs from the reviewed pin, review the changed instructions before use; do not assert equivalence.
2. UI UX Pro Max: use for a concrete knowledge gap (style, typography, UX, stack), not mandatory
   replacement of an existing brand. Verify Python and the complete script/data tree. With host
   authorization run a bounded search using the actual search.py path and supported flags. Prefer
   read-only Markdown output; do not use --persist or --force to create a second MASTER.md.
   Carry the query, source pin, result and adopted/rejected suggestions into the task evidence.
3. Google local analysis: enhance-prompt can structure a brief; extract-design-md can inspect source.
   Read their prerequisite and supporting files. Supply only accepted sections and canonical rules;
   no invented content. If an upstream instruction requires network access that is unavailable, report
   that prerequisite BLOCKED and use NOTTH local guidance instead of claiming full upstream execution.
   If a skill requires a different output path/format, request agreement for a derived export, identify
   its canonical source/revision, and never let the export become another editable master.
4. taste-design is an opinionated optional input, not a baseline. Do not execute it as-is when its
   bans, asymmetry, motion or density contradict approved project design/accessibility. Explain the
   conflict and use NOTTH direction guidance; do not call selective inspiration full skill compliance.
5. Stitch generation/editing: first verify an authorized configured Stitch MCP in the actual host,
   intended project and allowed write scope. Read the reviewed generate-design skill, enhance the
   scoped prompt and include the canonical design decisions. Use actual advertised tools, never invented
   API names. Inspect generated screens and retain real project/screen references and revision evidence.
   Upload only authorized content; never send private source or customer data just to improve a preview.
6. Missing skill/Python/MCP/network: report which route is unavailable and why. Continue with
   `harness-uiux-design-direction` + existing code preview tooling when accepted. An explicitly required
   editable Stitch/Figma/Penpot deliverable remains BLOCKED until available or substitution is approved.
7. Hand off actual provider/skill/version, inputs, outputs, decisions adopted, and limitations to
   `harness-uiux-design-system` and `harness-uiux-design-review`. Refresh canonical decisions only for
   authorized changes. Never infer visual quality from a successful tool call or generated DESIGN.md.

## Output
- Evidence of the exact skill/provider used, or explicit NOT_RUN/BLOCKED plus feasible local route.
- Source-linked suggestions or inspected design artifacts reconciled with the canonical design source.

## Constraints
- No automatic downloads, dependency installs, account connection, paid escalation or installer execution.
- External bodies are not vendored in NOTTH. Host executes them only after source/prerequisite review.
- Pin updates require maintainer review and refreshed examples/evaluation; a reference URL is not execution.
