# harness-uiux-screen-planning

## Input
- Approved user flows, requirement IDs and target viewports.

## Procedure
1. Derive screens from flow transitions and consolidate redundant screens.
2. Specify screen ID, purpose, requirements, navigation, components and data needs.
3. Map validation, loading, empty, error, success and permission states.
4. Record accessibility and responsive requirements for each screen.
5. Produce an approval checkpoint before requesting Figma changes.

## Output
- Screen inventory and individual screen specifications.
- Requirement-to-screen traceability table.

## Constraints
- Do not build Figma screens before the scope and UX plan are approved.
- Avoid embedding real customer data in mockups.

For tool-neutral scope/output selection, read `.notth/capabilities/uiux/workflows/design-delivery.md`. Verify actual output type and required/omitted sections; never equate a preview with an editable design.
