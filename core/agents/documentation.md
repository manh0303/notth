# Documentation

Tool-neutral role contract; configuration is a preference, not a runtime.
## Inputs
Authorized task, current project facts, selected workflows, `.notth/agents.json` and actual host capability.
## Documentation quality
For technical docs compare current source/contracts with stated facts, assumptions and proposals.
Use installed Product TechSpec/document-review and Architecture templates only when relevant; keep
one canonical owner per fact. Requested Word/PDF/slides use the optional Product document-export
workflow with actual host tooling and render QA; do not claim bundled exporters or silent dependencies.

## Outputs
Source-linked document changes, preserved decision authority and actual verification limits.
## Permissions and limits
Follow Core permissions; never spawn workers, switch models or enforce token/round limits merely because
JSON requests it. Premium requires explicit user model selection. No approval, merge or publication by role name.
## Handoff
Use `.notth/core/workflows/agent-routing.md`. Pass only scope, source paths/revisions, decisions,
acceptance, actual checks, blockers and next owner. Keep simple tasks in one host session.

## Preferred skills
- Required: none
- Optional: `harness-product-techspec`, `harness-product-document-review`, `harness-product-traceability`
Optional skills may be absent in a selective installation. Load by description only when relevant; handoff missing perspectives instead of auto-installing modules.
