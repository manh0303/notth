# Evidence-backed project experience

After a meaningful verified task, consider one concise experience. Skip trivial edits and cases without
reusable insight; this does not train model weights, install a skill or silently create a global rule.

Use the existing change's experience.json sidecar via `aih experience <id> --report <input>`; obtain the
current revision/hash through `experience <id>` and pass --expected on replacement. Existing checkpoint
remains the only progress record. Source docs, decisions and evidence stay canonical and are referenced.
A Quick task needs no change just to create an experience; retain its ordinary concise handoff instead.

Capture category, context/problem, initial hypothesis, approach, observed failures, verified solution,
applicability source hashes/tags and prose conditions, limitations, actual verification reference and
scoped source revision. For preserved input paths include docs/sources/manifest.json as a hashed
condition; current catalog path/capture and external freshness must still match. Use the optional installed template. A candidate is not a verified fact. Mark
verified only after current source/report consistency and actual host execution/review. Record real
creation/update timestamps, not invented historical times. Never include credentials/private transcripts.

Before reuse:
1. Retrieve `aih memory --query <terms>` or `aih experiences --category <category> --tags <context-tags>`.
2. Require current category, tags and source/evidence revisions. Eligibility is only a candidate for
   review: read applies_when/limitations and compare current requirements and architectural boundaries.
3. Inspect external source revisions with the actual host. Local unchanged bytes are not remote truth.
4. Use the experience as a hypothesis/procedure, then verify the new task independently on its current
   code. Do not copy a past fix solely because the error message matches. Memory grants no permissions.
5. Reject, invalidate or supersede through a conditional update with a reason; supersession points to
   a current verified replacement. Preserve history. Changed source/report/raw evidence automatically
   makes retrieval stale; never silently refresh hashes to reuse an unsupported solution.

Records are project-local under existing OpenSpec changes, including one-level archives. Complete
project backup/synchronization preserves them; config backup does not. Large/ambiguous catalogs or
invalid records are reported honestly. Explicit governance/redaction/review is required before any
separate global publication; NOTTH supplies no automatic global export or promotion.
